# i18n — đa ngôn ngữ (go-i18n v2 + vue-i18n)

Hệ thống đa ngôn ngữ 2 tầng:
- **Backend** (Go): `github.com/nicksnyder/go-i18n/v2` — message files, render theo `Accept-Language`
- **Dashboard** (Vue): `vue-i18n` — locale files TS, đồng bộ ngôn ngữ qua header `Accept-Language`
  gửi kèm mọi request → backend trả msg đúng ngôn ngữ (1 nguồn ngôn ngữ xuyên suốt)

Ngôn ngữ hỗ trợ: **vi** (mặc định) + **en** — thiếu key → fallback về vi.

---

# BACKEND (Go)

## Nguyên tắc (BẮT BUỘC)

1. **Message ID LUÔN literal tĩnh** — `i18n.T(lang, "error.invalid_api_key", ...)`.
   KHÔNG nối chuỗi/biến làm ID (`"error_" + code`) — goi18n extract/merge không
   thu được → phải tạo **key tĩnh/placeholder** cho từng biến thể.
2. Nội dung động qua **template data**: `{{.Scope}}`, `{{.Slug}}` — vd
   `apperr.Forbidden("api_key_scope", "error.api_key_scope").WithData(map[string]any{"Scope": scope})`.
3. `apperr.Xxx(code, msg)` — tham số msg giờ là **message ID** (không phải text).
   Response render theo `Accept-Language` của request (`core/i18n.Middleware`).
4. Default = `vi` — zero-config: không set gì → tiếng Việt như cũ.
5. Key chưa dịch/không tồn tại → trả về **chính ID** (dev thấy ngay key thiếu).

## Workflow thêm message mới

```bash
# 1. Dùng ID literal trong code (vi.json là nguồn)
# 2. Thêm vào core/i18n/messages/vi.json
# 3. Chạy merge → .i18n/translate.*.json liệt kê key chưa dịch
make i18n:merge
# 4. Dịch en.json (hoặc copy translate.en.json sang messages/en.json rồi dịch)
# 5. Chạy lại merge để xác nhận sạch key thiếu
```

## goi18n extract / merge — hành vi (đã research + verify)

- **`goi18n extract`** — quét Go source tìm `i18n.LocalizeConfig`/`i18n.Message`:
  - CHỈ thu được message khi code khai báo **nội dung translation** (`i18n.Message{ID, Other: "..."}`);
    `LocalizeConfig{MessageID}` không nội dung → **bị lọc sạch** (file rỗng — `NewMessageTemplate` trả
    nil khi không có plural template) → extract VÔ DỤNG với workflow file-based.
  - Nối chuỗi: chỉ hỗ trợ literal `"a" + "b"`; biến → không bắt được.
- **`goi18n merge`** — đường chính: `goi18n merge -sourceLanguage vi -outdir . -format json vi.json en.json`
  → tạo `active.vi.json` (runtime) + `translate.en.json` (danh sách key cần dịch, có hash để phát hiện
  nguồn đổi). Dịch xong en.json → merge lại → `active.en.json`.
- Kết luận: dùng **merge** (không extract) — key mới luôn thêm tay vào vi.json,
  merge sinh danh sách cần dịch cho các ngôn ngữ khác.

## Ngôn ngữ request

`Accept-Language` header → middleware set `ctxkey.LangKey` → đọc qua `i18n.Lang(c)`.
Hỗ trợ: `vi`, `en` (thiếu → fallback `vi` → trả ID). Thêm ngôn ngữ mới:
thêm file `messages/<lang>.json` + thêm vào switch của `Middleware` + bundle load.

## Message files

| File | Vai trò |
|---|---|
| `messages/vi.json` | NGUỒN (default) — key + tiếng Việt |
| `messages/en.json` | Bản dịch tiếng Anh |

Format: JSON `{ "id": { "other": "text {{.Field}}" } }` (chuẩn go-i18n — tiếng Việt
chỉ dùng plural form `other`, không phân biệt số).

# DASHBOARD (Vue)

`dashboard/src/i18n.ts` — `createI18n({ legacy: false, locale: vi, fallbackLocale: vi })`.
Lựa chọn ngôn ngữ lưu `localStorage['gvs_locale']` (default vi — zero-config).

## Cấu trúc

| File | Vai trò |
|---|---|
| `src/i18n.ts` | setup vue-i18n + `setLocale()` (đổi locale, lưu localStorage) |
| `src/locales/vi.ts` | NGUỒN (default) — key + tiếng Việt |
| `src/locales/en.ts` | Bản dịch tiếng Anh |

## Quy ước code

1. UI string (label/toast/title) → `t('section.key')` — KHÔNG hardcode text.
2. Component dùng `const { t } = useI18n()`; file ngoài component (vd `client.ts`)
   dùng `i18n.global.t('...')`.
3. Text nối biến → `t('apiKeys.totalNote', { total })` (message dùng `{{total}}`).
4. Tên ngôn ngữ hiển thị bằng CHÍNH ngôn ngữ đó (English / Tiếng Việt) — chuẩn
   quốc tế, không dịch.
5. Thêm message: sửa `vi.ts` (nguồn) + `en.ts` — không có extract/merge tự động
   (file TS — key khai báo tay, giống backend file-based).

## Đồng bộ ngôn ngữ với backend

`src/api/client.ts` request interceptor tự gắn:
`Accept-Language: en | vi` (đọc từ `localStorage['gvs_locale']`) → backend response
`msg` + validation meta đã đúng ngôn ngữ → toast hiển thị trực tiếp, không cần dịch
lại phía client. Đổi ngôn ngữ ở sidebar (nút Languages) → setLocale → request sau
tự đổi theo.
